# Сканер подписок

Находит забытые подписки в банковской выписке, показывает, какие
сервисы дублируют друг друга, и объясняет, как отключить лишнее.

Telegram-бот принимает выписку в PDF или CSV, за полсекунды разбирает
её и возвращает список подписок с оценкой: что дублируется, что стоит
проверить, что оставить. Для каждой подписки — пошаговая инструкция по
отмене со ссылкой на нужную страницу сервиса.

**Чем отличается от раздела «Подписки» в банковском приложении:** там
список того, что списывается. Здесь — поиск пересечений по функциям
(три видеосервиса делают одно и то же), инструкция отмены и посчитанная
экономия в рублях за год.

## Результаты

На пяти тестовых выписках с размеченным эталоном:

| Метрика | Значение |
|---|---|
| Транзакций разобрано | 3 164 |
| Подписок в эталоне | 49 |
| Обнаружение (precision / recall) | **1.000 / 1.000** |
| Только детектор, без LLM | 0.939 / 0.939 |
| Определение периодичности | 100 % |
| Именование сервисов вне справочника | 87–89 % |

На выписке без пересечений система возвращает **ноль рекомендаций** —
мы не выдумываем дубли там, где их нет (тест-кейс `case_03`).

### Проверить эти цифры

```bash

cd TehnoVibe---4
pip install -r requirements.txt
python scripts/evaluate.py
```

Ключи и интернет не нужны: тестовые выписки, эталоны и кэш ответов

## Как устроено

```
Выписка (PDF / CSV / XLSX)
  │
  ├─ парсер — колонки определяются автоматически
  ├─ нормализация мерчанта → справочник на 253 паттерна
  │    └─ [LLM] только для сервисов вне справочника
  ├─ группировка по сумме → медианный интервал → период
  ├─ пересечения по категориям → флаги → расчёт экономии
  │    └─ [LLM] план оптимизации, объяснения, письма
  │
  └─ Telegram-бот + Mini App
```

Подписки ищет **детерминированный алгоритм**, а не нейросеть. Поиск
повторяющегося платежа — это арифметика: её надо считать точно и
воспроизводимо, и только так можно измерить точность. Модель работает
там, где нужно суждение: распознать незнакомый сервис, решить, какую
из трёх подписок оставить, объяснить это человеческим языком.

Если модель недоступна, приложение продолжает работать: подписки и
экономия считаются без неё. В ответе есть флаг `llm_used`.

### Ответы модели проверяются

- **Справочник важнее модели.** Сервис, уже определённый по словарю,
  переименовать нельзя — иначе Apple Services превращается в iTunes и
  уезжает в музыкальный кластер, создавая ложное пересечение.
- **План проверяется на полноту.** Модель обязана предложить отключить
  все дубли, найденные алгоритмом. Проигнорировала — берём свой план.
- **Объяснение должно называть сервисы группы**, иначе это пересказ
  цифры.
- **Все суммы пересчитываются нами.** Числам модели не доверяем.

### Смена модели

Провайдер переключается переменной окружения или кнопкой в боте, код
при этом не меняется:

```
LLM_PROVIDER=gigachat   # GigaChat в облаке
LLM_PROVIDER=local      # Gemma 4 E4B на своём GPU
LLM_PROVIDER=http       # любая модель за HTTP
```

В облако уходят только названия мерчантов — без сумм и дат.

## Запуск

```bash
pip install -r requirements.txt
cp .env.example .env          # заполнить токен и ключ
python -m uvicorn backend.main:app --reload
```

Бэкенд отдаёт и API, и Mini App на `http://localhost:8000`,
документация — на `/docs`.

Бот запускается отдельно:

```bash
python bot/bot.py
```

### Переменные окружения

| Переменная | Назначение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен бота от @BotFather |
| `LLM_API_KEY` | ключ авторизации GigaChat |
| `LLM_SCOPE` | `GIGACHAT_API_PERS` для физлиц |
| `LLM_MODEL` | например `GigaChat-2` |
| `LLM_PROVIDER` | `gigachat`, `local` или `http` |
| `LLM_BASE_URL` | адрес модели при `LLM_PROVIDER=http` |
| `MINI_APP_URL` | HTTPS-адрес Mini App для кнопки в боте |

## Структура

```
backend/
  main.py            FastAPI: анализ, отмена, выбор модели, раздача фронта
  ml/parser.py       разбор выписок PDF, CSV, XLSX
  ml/detector.py     поиск подписок, пересечений, расчёт экономии
  ml/llm.py          слой модели: провайдеры, кэш, проверка ответов
bot/                 Telegram-бот на aiogram
frontend/            Mini App
contracts/           схемы данных, единый формат для всех частей
ai_core/prompts/     пять системных промптов
data/                справочник мерчантов, база отмены, тестовые выписки
scripts/             генераторы данных, замер точности, прогрев кэша
docs/                хендофф для защиты, инструкция по локальной модели
```

`contracts/schemas.py` — единый источник правды о формате данных.
FastAPI проверяет по нему ответы, фронт и бот на него ориентируются.

## Ограничения

Инструкции покрывают 43 сервиса. Для остальных их генерирует модель с
пометкой о непроверенности.

Мы не отменяем подписку за пользователя — банки не дают такого API.
Даём инструкцию и отмечаем результат с его слов.

Одно списание за период не позволяет вывести точную периодичность:
считаем годовой и помечаем это в интерфейсе.
